## 任务书

### 1. 问题描述

随着光伏发电产业的快速发展，电站运营方需要实时掌握各电站的发电量、发电效率、设备运行状态、节能减排效益等关键指标，并对海量运行数据进行存储与分析。

传统单机信息系统无法满足以下需求：
（1）海量发电数据的分布式存储（每年单站日发电数据 365 条以上，多站多年累积数据量大）；
（2）实时数据的快速采集与清洗（模拟采集终端产生的高频日志）；
（3）多维度统计分析（按日、月、年统计发电量、收入、减排量、发电效率）；
（4）大屏可视化监控（综合指标、趋势曲线、预测数据、设备实时状态）。

因此需要构建一个"光伏电站大数据监控与分析平台"：以 Hadoop 生态为底座，实现数据采集、清洗、存储、计算、分析、展示的全链路。

### 2. 功能要求

（1）**环境要求**：搭建 6 节点大数据集群，启动 HDFS、YARN、ZooKeeper、HBase、Kafka、Elasticsearch、MySQL、Redis 全部组件，满足"已开启 hadoop、hdfs、hbase 框架环境"的数据导入前置条件；

（2）**数据导入**：模拟生成电站日发电数据（电站、电表、逆变器、天气），经数据通道写入存储层；数据导入期间不进行其他操作，保证数据完整性；集群高可用，单个节点故障不影响数据传输；

（3）**数据存储**：结构化业务数据存 MySQL，海量发电数据可存 HBase，文件类数据存 HDFS；

（4）**后端接口**：实现登录认证（JWT + Redis）、电站信息管理、电价管理、售电合同管理、设备与厂商管理、阈值设置、实时/历史数据监控、巡检（项目/计划/点/管理）、工单管理、运行日报、异常检索、经验库等接口；

（5）**核心功能——电站发电综合及平均统计**：从 `k_wh_ammeter` 电表日发电表读取数据，计算累计发电量、日均发电量、累计收入、日均收入、今日收入、总 CO2 减排量、总节煤量、日均 CO2 减排量、日均节煤量共 9 项指标，并返回前端展示；

（6）**前端展示**：基于 Vue2 + Element UI + ECharts 实现首页大屏（9 项指标卡、近 30 天发电效率图、未来 30 天预测图、天气信息、电站地图、电表读数、故障列表）与各业务页面；

（7）**系统测试**：编写自动化测试脚本，对全部接口进行冒烟测试，对核心业务编写详细测试用例并记录测试报告。

### 3. 问题的解决方案

**技术选型**：以 Vue + ECharts 为前端，Spring Boot 为后端，HDFS 为底层存储，Spark 作为数据清洗和计算框架完成整体架构实现。

- 实时数据采集：SparkStreaming（消费 Kafka）
- 中间件：Kafka（消息缓冲）
- 数据计算分析框架：Spark
- 数据存储与持久化：HDFS、HBase、MySQL、Redis
- 对外查询接口：Spring Boot + MyBatis-Plus

**平台总体四层架构**（按数据流入与处理顺序）：

1. **数据导入层**：模拟采集数据 → Flume/Kafka → SparkStreaming 清洗，前置条件为 HDFS/HBase 环境已开启；
2. **数据存储层**：非结构化文件存 HDFS，海量业务数据存 HBase，结构化数据存 MySQL，高频访问缓存用 Redis；
3. **数据分析层**：Spark 对存储数据进行清洗、聚合、统计，实时数据经 Kafka 流入 SparkStreaming 清洗后写入 MySQL 供后端调用；
4. **应用层**：Spring Boot 对外暴露 REST 接口，Vue 前端实现可视化平台（大屏 + 业务页面）。

**"电站发电综合及平均统计"解决方案**：以 `k_wh_ammeter`（电表日发电表）为数据源，用 MyBatis-Plus 的 `selectCount(select("distinct power_date"))` 获取累计天数，`selectList(select("kwh"))` 获取全部日发电量并求和得累计发电量；除以天数得日均发电量；再乘以电价系数（MONEY_FORMAT=6000）换算累计收入（万元）；乘以减排系数（REDUCE_CO2_FORMAT=997 g/kWh、REDUCE_COAL_FORMAT=400 g/kWh）换算 CO2 减排量与节煤量。前端 `getStationAllAndAverage()` 调用 `GET /screen/stationAllAndAverage` 接口，将返回值渲染到首页指标卡。

# 第一章 系统概述

## 1.1 项目背景

光伏发电是新能源产业的重要组成部分。电站运营中需要实时监控发电量、发电效率、设备状态，并统计节能减排效益。由于发电数据量大、来源多（电站、电表、逆变器、天气传感器），传统单机系统难以满足存储与分析需求，因此采用大数据技术栈构建监控分析平台。

## 1.2 项目目标

1. 搭建完整的大数据集群实验环境（HDFS、YARN、ZK、HBase、Kafka、ES、MySQL、Redis）；
2. 实现从模拟数据生成、采集、清洗、存储到查询展示的完整数据链路；
3. 实现电站发电综合及平均统计等大屏核心功能；
4. 提供完整可运行的前后端系统与自动化测试。

## 1.3 系统特性

- **分布式存储**：发电数据存储于 HDFS/HBase，结构化数据存 MySQL；
- **实时计算**：SparkStreaming 消费 Kafka 消息进行实时清洗；
- **缓存加速**：Redis 保存登录会话与令牌，提升接口性能；
- **可视化**：ECharts 图表 + Element UI 组件实现大屏与业务页面；
- **一键部署**：提供桌面一键启动脚本，可冷启动全部 9 项集群组件。

# 第二章 系统需求分析

## 2.1 任务概述

实训任务在"基础代码框架"基础上开发。本任务聚焦"电站发电综合及平均统计"功能：

1. **确定数据来源**：`k_wh_ammeter`（电表日发电表）——字段 `power_date`（发电日期）、`kwh`（日发电量）、`end_kwh`（表底读数）；
2. **查询数据并计算**：统计累计发电量、日均发电量、累计收入、日均收入、今日收入、总 CO2 减排量、总节煤量、日均 CO2 减排量、日均节煤量；

同时要求前后端链路完整可用：登录（JWT+Redis）→ 大屏接口 → 前端渲染。

## 4.1 登录认证模块（identity）

### 4.1.1 功能说明

实现用户名密码登录、JWT 令牌签发、Redis 会话管理、请求鉴权、退出登录、密码修改。

### 4.1.2 涉及类

| 类 | 职责 |
|----|------|
| TokenLoginFilter | 登录过滤器：解析参数 → Security 认证 → 签发令牌 → 写 Redis → 响应头返回 Authorization |
| TokenAuthenticationFilter | 鉴权过滤器：白名单放行，其余请求校验 JWT 签名 + Redis 令牌存在性 |
| TokenUtil | JWT 生成/校验（HS256，密钥固定，有效期 EXP_TIME=120 分钟） |
| AuthController / UserController | /login、/register、/user/list、/changePassword、/logout |
| SysAuthMapper | 查询用户权限/菜单 |

### 4.1.3 关键流程

1. 前端 POST `/api/login`（{name, password}）→ 开发代理转发到本地后端 8113；
2. `TokenLoginFilter.attemptAuthentication` 解析请求参数（JSON 或表单），交给 Spring Security 认证；
3. 认证成功：`TokenUtil.genToken(payload)` 生成 JWT（claims：id、name，exp=now+120min）；
4. 写 Redis：`userId → token`（有效 120min）；`token → 权限集合 Set`（有效 120min）；
5. 响应头 `Authorization: <JWT>`，并加 `Access-Control-Expose-Headers` 让浏览器可读；
6. 前端 axios 响应拦截器保存 Authorization 到 localStorage，后续请求头携带；
7. 每次请求：`TokenAuthenticationFilter` 校验 JWT 有效 + Redis 有该 token → 放行；否则 401（"Token失效"/"未登录"）；
8. 重复登录会使旧 token 失效（单会话）。

## 4.2 电站发电综合及平均统计（任务核心功能）

### 4.2.1 功能说明

计算电站累计发电量、日均发电量、累计收入、日均收入、今日收入、总 CO2 减排量、总节煤量、日均 CO2 减排量、日均节煤量共 9 项指标，供前端大屏首页展示。

### 4.2.2 涉及类

### 4.2.3 实现逻辑与计算公式

```
dayNum   = SELECT COUNT(DISTINCT power_date) FROM k_wh_ammeter        // 累计发电天数
allKWh   = Σ(kwh)                                                     // 累计发电量 kW·h
averageKWh  = allKWh ÷ dayNum                                         // 日均发电量
allInCome   = allKWh × 6000 ÷ 10000                                   // 累计收入（万元）
todayKWh    = Σ(kwh) WHERE power_date = 今日                           // 今日发电量
todayInCome = todayKWh × 6000 ÷ 10000                                 // 今日收入（万元）
averageInCome = allInCome ÷ dayNum                                    // 日均收入（万元）
allReduceCO2 = allKWh × 997 ÷ 1000                                    // 总 CO2 减排（t）
allReduceCoal = allKWh × 400 ÷ 1000                                   // 总节煤（t）
averageReduceCO2  = allReduceCO2  ÷ dayNum                            // 日均 CO2 减排（t）
averageReduceCoal = allReduceCoal ÷ dayNum                            // 日均节煤（t）
```

### 4.2.4 核心代码

```java
@Override
public StationAllAndAverOutput stationAllAndAverage() {
    StationAllAndAverOutput output = new StationAllAndAverOutput();
    // 获取总共的天数
    Integer dayNum = kWhAmmeterMapper.selectCount(new QueryWrapper<KWhAmmeter>().select("distinct power_date"));
    // 统计累计发电量
    List<KWhAmmeter> allAmmeter = kWhAmmeterMapper.selectList(new QueryWrapper<KWhAmmeter>().select("kwh"));
    output.setAllKWh(allAmmeter.stream().mapToDouble(KWhAmmeter::getKwh).sum());
    // 计算日均发电量
    output.setAverageKWh(BigDecimal.valueOf(output.getAllKWh())
            .divide(BigDecimal.valueOf(dayNum), 2, BigDecimal.ROUND_HALF_UP).doubleValue());
    // 计算累计收入
    output.setAllInCome(BigDecimal.valueOf(output.getAllKWh())
            .multiply(BigDecimal.valueOf(ScreenConstant.MONEY_FORMAT))
            .divide(BigDecimal.valueOf(10000), 2, BigDecimal.ROUND_HALF_UP).doubleValue());
    // 获取今日发电量
    List<KWhAmmeter> today = kWhAmmeterMapper.selectList(new QueryWrapper<KWhAmmeter>()
            .eq("power_date", DateUtil.getToDayDate()));
    output.setTodayInCome(BigDecimal.valueOf(today.stream().mapToDouble(KWhAmmeter::getKwh).sum())
            .multiply(BigDecimal.valueOf(ScreenConstant.MONEY_FORMAT))
            .divide(BigDecimal.valueOf(10000), 2, BigDecimal.ROUND_HALF_UP).doubleValue());
    // 日均收入、总/日均 CO2 减排量、总/日均节煤量（同类公式）
    ...
    return output;
}
```

### 4.11.4 前端修复记录（实训期间发现并解决）

1. **登录 mock 问题**：`Login.js` 中 `USE_MOCK=true` 导致登录返回假 token（mock-token-xxx），后端鉴权 401 循环退出登录 → 改为 `USE_MOCK=false`，去掉 catch 静默降级；
2. **登录代理指向远程云服务器**：vue.config.js 中 `/api/login` 默认代理到 `101.43.206.109:8787`（远程签发 token 本地不认）→ `.env` 增加 `VUE_APP_AUTH_API=http://localhost:8113`，默认值改为本地；
3. **token 持久化**：`persistLogin` 改为从响应头/本地存储取真实 token，不再兜底伪造；
4. **侧边栏点击无反应**：后端菜单为层级结构（父级 menuUrl 为 null + childs），`Left.vue` 原只渲染扁平项 → 改为 `el-submenu` 层级渲染；
5. **侧边栏点击回登录页**：11 个菜单 URL 无前端路由（匹配 `*` 兜底路由指向 Login）→ 补齐 dataSearch/dataAnalysis/authority 路由，`*` 兜底改为 `redirect: '/home'`；
6. **index.html 高德地图**：AMap JS 由外部 CDN 引入（外网可达）。
