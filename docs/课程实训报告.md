## 任务书

**1. 问题描述**

光伏电站运营中需要实时掌握发电量、发电效率、节能减排等指标。本项目构建光伏电站大数据监控与分析平台：模拟采集电站发电数据，经 Kafka 缓冲、SparkStreaming 清洗后存入 HDFS/HBase/MySQL，由 Spring Boot 提供查询接口，前端采用 Vue + Element UI + ECharts 实现大屏与业务页面展示。

**2. 功能要求**

（1）搭建大数据集群环境（HDFS、HBase、Kafka、Spark、ES、MySQL、Redis）；
（2）后端实现登录认证、电站管理、电价管理、售电合同、设备管理、数据监控、阈值设置、巡检运维、工单、运行日报等接口；
（3）实现"电站发电综合及平均统计"：累计发电量、日均发电量、累计收入、日均收入、今日收入、CO2 减排量、节煤量等指标的计算与展示；
（4）前端实现大屏首页与各业务页面，数据可视化展示；
（5）编写自动化测试脚本对系统进行测试。

**3. 问题的解决方案**

总体架构按四层设计：数据导入层（模拟采集 → Flume → Kafka → SparkStreaming 清洗）→ 数据存储层（HDFS/HBase/MySQL/Redis）→ 数据分析层（Spark 统计计算）→ 应用层（Spring Boot API + Vue 可视化）。综合及平均统计基于 `k_wh_ammeter` 电表日发电表聚合计算，前端 `getStationAllAndAverage()` 接口获取并展示。

## 第一章 系统概述

本项目构建光伏电站大数据监控与分析平台，实现从数据采集、实时清洗、分布式存储到查询接口与可视化展示的完整链路。集群共 6 个节点：master（HDFS NameNode、YARN ResourceManager、HBase Master）、slave1（DataNode、RegionServer、Redis）、slave2（DataNode、RegionServer、MySQL）、client1~3（开发节点）。

技术架构四层：

| 层次 | 技术 |
|------|------|
| 应用层 | Vue2 + ElementUI + ECharts，Spring Boot（端口 8113），Redis 缓存 |
| 数据分析层 | SparkStreaming（消费 Kafka）、Spark 预测 |
| 数据存储层 | HDFS、HBase、MySQL、ElasticSearch |
| 数据导入层 | 模拟数据生成、Flume、Kafka |

技术清单：消息中间件 Kafka、数据采集清洗 SparkStreaming/Flume、存储 HDFS/HBase/MySQL/Redis、实时计算 SparkStreaming、资源调度 YARN、集群协调 ZooKeeper、日志监控 ELK。

## 第四章 系统主要模块详细设计及实现

### 4.1 登录认证模块

`TokenLoginFilter` 校验用户名密码，成功后签发 JWT（120 分钟有效）并写入 Redis；`TokenAuthenticationFilter` 对请求鉴权，校验 JWT 签名与 Redis 令牌，失败返回 401。单会话：重复登录使旧令牌失效。

### 4.2 电站发电综合及平均统计

接口：`GET /screen/stationAllAndAverage`。实现步骤：

1. 统计电表表去重天数 dayNum；
2. 累计发电量 allKWh = Σ(kwh)；
3. 日均发电量 averageKWh = allKWh ÷ dayNum；
4. 累计收入 allInCome = allKWh × 6000 ÷ 10000（万元）；
5. 今日收入 = 今日电表 Σkwh × 6000 ÷ 10000；
6. CO2 减排量 = allKWh × 997 ÷ 1000（t）；节煤量 = allKWh × 400 ÷ 1000（t）；
7. 日均 CO2 / 日均节煤量同理。

实测返回：累计发电量 448821.33 kW·h，日均发电量 4826.04 kW·h。

### 4.3 前端大屏首页

`src/views/Home/Home.vue` 展示 9 项指标卡（累计发电量、日均发电量、累计收入、日均收入、今日收入、总 CO2 减排量、总节煤量、日均 CO2 减排量、日均节煤量）；`src/api/Home/Home.js` 封装大屏全部接口。

## 第五章 系统测试

### 5.1 测试目的

验证接口正确性、功能完整性与端到端可用性。

### 5.2 测试用例及结果

冒烟测试：覆盖 19 个控制器 43 项接口（登录、字典、电站、大屏、设备、监控、巡检、工单、日报、查询），**43/43 全部通过**。

业务用例测试（用例 13-23）：电价与合同的新增/分页/详情/删除、逻辑删除、重复名称校验等 14 项，**14/14 全部通过**。

### 5.3 测试总结

测试发现并修复的问题：Redis 未启动导致登录失败；16 张表缺列；前端 mock 登录导致 401 循环；侧边栏层级菜单与缺失路由；框架副本缺实体类导致编译失败；inotify 监听上限；Kafka broker.id 冲突；ZK 集群配置不完整等。修复后全部用例通过。
